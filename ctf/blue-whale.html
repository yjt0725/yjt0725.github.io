Blue Whale

Docker Image의 Layer를 분석하여 삭제된 Flag의 흔적 찾기

2026.08.17 · yjt0725
Docker Docker Layer Dive Linux Wargame

1. 문제

이번 문제의 목표는 주어진 Docker Image를 분석하여 삭제된 Flag를 찾아내는 것이었다.

처음에는 Docker Container를 실행해서 내부 파일을 찾는 문제라고 생각했지만, 문제에서 dive라는 힌트가 주어졌다.

이 문제의 핵심은 최종 Container가 아니라 Docker Image의 이전 Layer를 분석하는 것이다.

2. Docker Image 다운로드

먼저 문제에서 제공된 Docker Image를 다운로드했다. 

docker pull dreamhackofficial/blue-whale:1

다운로드된 Image는 다음 명령어로 확인했다. 

docker images

결과에서 다음 Image가 존재하는 것을 확인할 수 있었다. 

dreamhackofficial/blue-whale:1

3. Docker Layer란?

Docker Image는 하나의 파일처럼 보이지만, 실제로는 여러 개의 Layer가 순서대로 쌓여 만들어진다.

Ubuntu 설치
↓
Python 설치
↓
Flag 추가
↓
Flag 삭제
↓
최종 Image

중요한 점은 뒤의 Layer에서 파일을 삭제하더라도 이전 Layer에는 파일의 흔적이 남아 있을 수 있다는 것이다.

따라서 최종 파일 시스템에서 Flag가 보이지 않더라도 과거 Layer를 조사하면 찾을 가능성이 있다.

4. Dive

Docker Image의 Layer를 분석하기 위해 dive라는 도구를 사용했다. 

winget install --id wagoodman.dive

설치 후: 

dive --version

설치 직후 명령어를 찾지 못하는 문제가 있었는데, 설치 과정에서 PATH 환경 변수가 변경되었기 때문이었다.

PowerShell을 완전히 종료한 후 다시 실행하니 정상적으로 사용할 수 있었다.

5. Docker Image 분석

다음 명령으로 Blue Whale Image를 Dive에서 열었다. 

dive dreamhackofficial/blue-whale:1

Dive의 왼쪽에는 Docker Image를 구성하는 Layer가 표시되고, 오른쪽에는 해당 Layer 시점의 파일 시스템이 표시된다.

6. 수상한 Layer 발견

Layer를 하나씩 확인하던 중 다음 명령을 발견했다. 

COPY ./deploy/flag /home/chall/flag

즉 원래는 다음 위치에 Flag 파일이 존재했다. 

/home/chall/flag

이후 작업 디렉터리가 변경된다. 

WORKDIR /home/chall

그리고 가장 중요한 명령어가 등장했다. 

RUN touch `python3 -c "print(open('./flag', 'r').read())"`

7. 명령어 분석

처음에는 이 명령어가 상당히 복잡해 보였다. 하지만 안쪽부터 나누어 보면 이해하기 쉽다. 

open('./flag', 'r').read()

이 부분은 flag 파일을 열고 내용을 읽는다.

그리고: 

print(open('./flag', 'r').read())

Flag의 내용을 출력한다.

이 출력 결과가 바깥쪽의 touch 명령어의 인자로 전달된다.

예를 들어 Flag가 다음과 같다고 가정하면: 

DH{example_flag}

실제로 실행되는 명령은 다음과 비슷해진다. 

touch DH{example_flag}

즉 Flag의 값 자체를 이름으로 가지는 파일이 생성된다.

8. 그런데 파일이 왜 없었을까?

바로 다음 Layer에서 다음 명령어가 실행되고 있었다. 

RUN rm *

현재 위치가 /home/chall이므로 해당 디렉터리의 파일들이 삭제된다.

flag 파일 존재
↓
Flag 내용을 읽음
↓
Flag 값을 파일 이름으로 생성
↓
rm * 실행
↓
파일 삭제

따라서 최종 Image에서는 해당 파일을 볼 수 없지만, 이전 Layer에는 파일이 생성되었던 흔적이 남아 있었다.

9. Flag 찾기

Dive에서 touch 명령이 실행된 Layer를 선택한 뒤 Layer 변경 사항을 확인했다.

그 결과 /home/chall 아래에서 DH{...} 형태의 파일 이름을 확인할 수 있었다.

실제 Flag 값은 Write-up에서는 공개하지 않았다.

10. 막혔던 부분

Docker Engine이 실행되지 않음

처음에는 docker version 실행 시 Docker Linux Engine에 연결할 수 없다는 오류가 발생했다.

Docker Desktop을 실행하고 Engine이 정상적으로 동작한 이후 해결되었다.

WSL과 WSL2

Windows에서 Docker Desktop은 Linux Container를 실행하기 위해 일반적으로 WSL2 기반 환경을 사용한다는 것도 이번에 알게 되었다.

Dive 설치 후 실행되지 않음

Dive를 설치했음에도 PowerShell에서 명령어를 찾지 못했다.

설치 과정에서 PATH가 변경되었고, 기존 PowerShell에는 변경된 PATH가 반영되지 않았기 때문이었다.

PowerShell을 종료하고 다시 실행하여 해결했다.

11. 배운 점

이번 문제를 통해 Docker Image가 단순한 하나의 파일이 아니라 여러 Layer의 조합으로 이루어진다는 것을 직접 확인할 수 있었다.

특히 Dockerfile에서 파일을 삭제했다고 해서 이전 Layer의 데이터까지 반드시 사라지는 것은 아니라는 점이 흥미로웠다.

또한 복잡해 보이는 Shell 명령도 안쪽부터 하나씩 분석하면 실제 동작을 이해할 수 있다는 것을 배웠다.

12. 핵심 정리

Docker Image에서 파일이 삭제되었더라도 이전 Layer에 흔적이 남을 수 있다.

Dive를 이용해 Layer를 확인하고, Flag 내용을 파일 이름으로 만드는 touch 명령이 실행된 시점을 분석하여 삭제되기 전 Flag를 확인할 수 있었다.
